## 约定

- **保持扁平**：同一领域出现**第二份**记录时才为该领域建子文件夹，按子系统命名（例如 `mcp/`、`multi-window/`）。
- **不按状态分层**：没有 `active/` 与 `archive/`；哪份是现行由上面状态一列回答，而不是靠文件搬家。
- **每份记录自洽**：结论与理由并存，原始问题与被否掉的方案保留（可用删除线），决定注明日期；实现细节与测量数字写进记录本身，`FEATURES.md` 保持不含测量。
- 删改条目时留意跨文档引用：其它文件按路径或小节标题引用这些记录，改动后跑一次文档审计。
- **日志不得自触发**：日志写的是用户可见的输出通道，而写输出会改变输出文档自身的可见范围。因此任何由可见范围/可见编辑器/文档变化监听器触发的路径，都必须**只处理自己真正装饰或渲染的文档**（输出通道、评论输入框所在文档、普通文件一律忽略），并且**只在报告的明细真正变化时才写那行日志**；反过来，说"日志只在变化时写"的路径不要在别处再无条件重写同一行。这两条规则是为了不再出现"日志写进输出 → 输出文档事件 → 重新计算 → 又写同一行"的自触发循环。
