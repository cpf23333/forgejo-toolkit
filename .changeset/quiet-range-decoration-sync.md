'forgejo-toolkit': patch
---

Stop the pull request comment decorations from driving themselves. With `forgejoToolkit.debug` on and one expanded multi-line comment thread, the extension filled the "Forgejo Toolkit" output channel with `Thread range decorations applied per visible editor: …` lines without any user interaction, burning CPU, and clearing the channel started it again: the visible-ranges listener re-applied the decorations, that re-apply wrote the debug line, and writing it changed the output editor's own visible ranges — which re-triggered the listener, endlessly. Two changes end it. The per-editor detail is now written only when it actually changes, so an identical re-application is silent; and the visible-ranges trigger now ignores every document these decorations never touch — the output channel, the comment-input documents and any other file — so neither the extension's own log output nor editing a comment box schedules decoration work at all. Decorations are also no longer re-painted when the computed range set for an editor is unchanged. The diagnostic itself is unchanged and still reports, on every genuine change, which visible editor got how many ranges and which got zero, so a "the highlight misses lines" report is still diagnosable with `forgejoToolkit.debug` on.
