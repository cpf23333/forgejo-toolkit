Hand the local MCP broker over between windows without a reload. The broker binds one endpoint per user profile, so only one window can serve it: the first window to start owns it and every window started afterwards steps aside silently, writing no registration of its own. Those windows do not give up — each re-reads the registration file every few seconds and checks whether the process id recorded in it is still alive — so when the owner closes (its `deactivate()` removes the file) or is killed (the file is left behind with a dead process id), one of them binds the endpoint itself, re-registers with its own live pid and starts logging `MCP broker listening at …`. A shim launched from `mcp.json` reaches the new owner with no client-side change, and the token still never leaves SecretStorage or the extension host. There is deliberately no lock and no election protocol: the watching windows just try to bind, and whichever `listen` succeeds owns the broker. What the handover cannot rescue is the session that was already running when the owner died — its forwarder loses its connection, writes one info line and exits — but starting that session again forwards through the new owner within a few seconds. Two profiles of the same user share the endpoint as well, because it is derived from the user name and home directory rather than from the profile.
