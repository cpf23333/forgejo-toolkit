Probe an instance's version once for the whole machine, not once per window, and keep the low-version gate alive for the length of a session. The shared probe cache now coordinates the probe itself: the window that decides to probe first records a marker beside the entry, and a second window that needs the same version waits for that result — bounded at ten seconds, and always failing open to probing itself when the wait expires, when the marker's owner is gone, or when the shared state cannot be read — instead of sending a duplicate request. Two windows claiming the marker in the same instant can still both probe, because `globalState` has no atomic read-modify-write; the cost is one extra request, never a wrong gate. The too-old-version warning now belongs to the window that probed: the notice is recorded with the shared entry, a window that adopted the value stays quiet, and a window that lost the marker race re-reads the record and skips its own notice, so the warning is raised once for the whole machine. Finally, the Actions version gate renews itself at the point of use: when the recorded version is unknown or has expired past the one-minute TTL, the gated call awaits a probe (through the same single-flight coordination) before evaluating the gate, so a long session no longer silently loses the gate — there is no periodic timer, and the probe's own request timeout bounds the wait, with "unknown" still failing open.
